# Changelog

This file tracks real changes to this repository. For the rules on how entries
here should be written, see CHANGELOG_TEMPLATE.md.

### Initial game and deployment (round one)

1. Created the single-player browser Snake game as a self-contained HTML file with a canvas renderer, arrow key and WASD controls, wall and self collision, a score display, and restart after game over.
2. Replaced the fixed-rate game loop with a self-rescheduling timer so the tick delay can change during play. The game starts slower and speeds up as food is eaten, down to a configurable floor.
3. Replaced the single stored direction with a capped input buffer. Each turn is validated against the last queued direction rather than the committed one, which closes a reversal that could kill the snake when two keys were pressed inside one tick. The buffer holds at most two turns and drops no-op repeats.
4. Rebuilt the game as an authoritative multiplayer server in Node.js. One process holds the game state, serves the client, and exposes the captcha endpoints. The board supports one to four live players with no accounts.
5. Added a spectator queue for connections past the fourth player. A spectator takes over a freed slot after a short delay so they have time to take control. When four or fewer players are connected, a dead player simply respawns.
6. Added player-versus-player scoring. Running into another snake body kills the mover and awards the other player a 10 point bonus with 3 segments of growth. Head-on collisions kill both players with no bonus.
7. Added daily and all-time top 5 high score boards with arcade-style 3 letter initials entry, persisted to a JSON file. The daily board resets when the calendar date changes.
8. Added a simple math captcha that issues a one-time, short-lived token before a WebSocket connection is accepted. It is intended to sit behind a Cloudflare filter, which is expected to do the real bot filtering.
9. Fixed a spawn placement check that could drop a new snake on top of an existing one, so a fresh snake now spawns only where all three of its starting cells are clear.
10. Bound the Node process to 127.0.0.1 so it is not directly reachable, with Apache as the sole public entry point. Added a 30 second WebSocket keepalive ping because Cloudflare closes idle proxied WebSocket connections after about 100 seconds.
11. Added an Apache reverse-proxy virtual host on a dedicated hostname so the game does not collide with the existing static site served from another virtual host on the same server.
12. Added a systemd unit, a one-command install script, a one-command uninstall script, and setup documentation. The installer detects an existing checkout or clones the repository, installs Node.js when needed, deploys the app, creates an unprivileged service user, and adds the Apache virtual host without modifying existing sites. The uninstaller backs up the high score file before removing the app.

### Generic hostname, TLS, and packaging (round two)

13. Made the deployment hostname generic. The repository now ships a single Apache vhost template, deploy/fillmeout.example.com.conf, instead of a vhost named for one specific domain. The installer copies the template and substitutes the chosen hostname into /etc/apache2/sites-available/<hostname>.conf. The earlier fixed-name vhost was removed.
14. Added an interactive hostname prompt to the installer. On the first run there is no default and a valid hostname must be entered. On a later run the previously used hostname, saved in /etc/multisnake/last-domain, is offered as the default and reused when the prompt is answered with an empty line. An explicit DOMAIN environment variable still overrides the prompt for non-interactive runs, and the prompt reads from the controlling terminal so it also works under the curl pipe.
15. Added retirement of a previous hostname on the installer. When a repeat run uses a different hostname than the saved one, the installer disables and removes the old vhost files, including the certbot-generated -le-ssl variant, so an orphaned site is not left enabled alongside the new one.
16. Added TLS provisioning to the installer using Let's Encrypt through certbot. The initial implementation used the HTTP-01 (port 80) challenge with the Apache plugin, then it was changed to the DNS-01 challenge through the Cloudflare API. DNS-01 was chosen because it needs no inbound port 80, so the DNS record can stay proxied through Cloudflare, whereas HTTP-01 fails when Cloudflare proxying or the Always Use HTTPS setting intercepts the challenge request. The Apache installer still writes the :443 vhost and the 80 to 443 redirect. The game is served on 443.
17. Made TLS setup safe on hosts that already run certbot. Certbot and its plugins are installed only when certbot is not already present, so an existing certbot and its renewal schedule are left alone. The installer never edits certbot.timer or any cron job, since installing the Debian package already provides a twice-daily renewal timer that covers every certificate, including this one. If a certificate for the hostname already exists it is reused rather than reissued, which avoids rate limits and does not disturb other certificates.
18. Added handling of the Cloudflare API token and email for TLS. The token can be provided as CF_API_TOKEN, reused from an existing per-hostname credentials file, or entered at a hidden prompt. It is written to /etc/letsencrypt/cloudflare-<hostname>.ini with mode 600 and reused at each renewal, since certbot records the path but not the contents. The email can be provided as CERTBOT_EMAIL or entered at a prompt, and a blank value registers without an email. TLS can be skipped entirely with ENABLE_TLS=no, and the propagation wait is adjustable with CF_PROPAGATION.
19. Updated the uninstaller for the generic flow. It reads the hostname from /etc/multisnake/last-domain, or from DOMAIN if set, so it removes the correct vhost, certificate, and Cloudflare credentials file no matter which domain was used. It removes both the plain and the -le-ssl vhost files, deletes only this hostname certificate with certbot delete so other certificates and the shared renewal timer are untouched, removes the per-hostname credentials file, backs up the high score file to /root, and removes the installer state directory. REMOVE_CERT=no keeps the certificate and credentials.
20. Added a source-snapshot release workflow. Because the project ships source only with nothing to compile, the workflow packages the tagged commit into .tar.gz and .zip archives with git archive and attaches both to a GitHub Release, rather than building binaries. Base token permissions are read-only with write elevated only on the release job, a concurrency group keyed on the tag prevents a re-pushed tag from racing an in-progress publish, and the publish step fails if no archive is produced. Action pinning to commit SHAs is left off by default with a directive to ask before enabling it, since pinned actions require ongoing maintenance the project does not have.
21. Added community-health files filled in for this repository: a Code of Conduct based on Contributor Covenant 2.1, a Contributing guide with local test steps for the game, a Security policy pointing at GitHub Security Advisories, bug report and feature request issue templates with valid front matter, and a pull request template. Placeholder tokens for the project name and repository URL were replaced with the real values, and the security policy support table was converted to plain text to keep the files ASCII.
22. Wrote the project README covering the feature set, requirements, the one-command install and uninstall, the interactive hostname prompt, the DNS-01 TLS flow with Cloudflare token scoping, the configuration keys, service operation, the repository layout, and the known limitations.
